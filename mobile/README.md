# KLS Hostel Complaints — Mobile app

Expo (React Native) client for the existing `server/` API. Same database, same
REST endpoints, same role model as the web `client/`.

## Stack

- **Expo SDK 57** (managed workflow) + **expo-router** (file-based routing)
  — must match the Expo Go version installed on your device
- **NativeWind v4** (Tailwind classes)
- **TanStack Query** + **axios** — same data layer as the web client
- **expo-secure-store** — refresh token; access token stays in memory
- **expo-image-picker** — complaint photo attachments

`mobile/` is intentionally **not** an npm workspace (it keeps its own
`node_modules`) so Metro needs no monorepo hoisting config.

## Auth model

The web client uses httpOnly cookies. Mobile can't read those, so the app
sends `X-Client: mobile` and the server (see the auth changes below) also
returns `{ accessToken, refreshToken }` in the login / refresh / change-password
response bodies. The app:

- keeps the **access token in memory**, attached as `Authorization: Bearer …`
- persists the **refresh token in the OS keystore** (`expo-secure-store`)
- on cold start, exchanges the stored refresh token via `POST /api/auth/refresh`
- refreshes once on any 401 and retries, else signs out (mirrors
  `client/src/api/client.js`)

### Backend changes this depends on (already applied)

| File | Change |
|---|---|
| `server/src/middleware/auth.js` | `requireAuth` also accepts `Authorization: Bearer` |
| `server/src/routes/auth.routes.js` | `/login`, `/refresh`, `/change-password` return `tokens` in the body **only** when `X-Client: mobile`; `/refresh` also reads the token from the body / Bearer header |
| `server/src/config/env.js` | `CLIENT_ORIGIN` is now a comma-separated list |

All are backward-compatible — the web client is unaffected.

## Running it

```bash
cd mobile
npm install
npx expo install --fix       # reconcile native dep versions to the SDK
npx expo start -c
```

If Expo Go reports an **SDK mismatch**, align the project to whatever SDK your
installed Expo Go uses (it upgrades often):

```bash
cd mobile
rm -rf node_modules package-lock.json
npm install
npx expo install expo@^57.0.0      # ← the SDK your Expo Go shows
npx expo install --fix             # rewrites RN / expo-* / react to that SDK
npm install nativewind@latest tailwindcss@latest
npx expo start -c
```

Then press `a` (Android emulator), `i` (iOS simulator), or scan the QR with
Expo Go on a physical device.

### Point it at your API

A phone can't reach `localhost`. Set the API base URL (LAN IP, tunnel, or
deployed host) one of these ways:

- `mobile/.env` → `EXPO_PUBLIC_API_URL=http://192.168.1.20:4000`
- or edit `expo.extra.apiUrl` in `mobile/app.json`

The server must listen on `0.0.0.0` (it does) and the device must be on the
same network. Uploaded images load from `<API_URL>/uploads/...`.

## Phase 2c — push notifications (DONE)

**Backend** (`server/`):
- `Device` model (`prisma/schema.prisma`) + migration
  `20260903120000_add_device_push_tokens`
- `POST /api/devices` / `DELETE /api/devices/:token` (`routes/device.routes.js`)
- `services/push.js` — Expo Push HTTP API, prunes dead tokens, never throws
- `complaint.routes.js` fires a push on: new complaint (→ assignee), forward,
  ETA set, resolve/reject, close, new comment (→ the other party; the actor is
  always excluded)

**Mobile**:
- `src/push/registerPush.js` — permission + Expo token, registers on login,
  unregisters on logout, routes notification taps to `/complaint/[id]`
- wired into `AuthContext` and the root layout

> ⚠️ Remote push does **not** work in Expo Go on Android (SDK 53+). Test it
> with a dev build or the EAS APK. The code degrades to a no-op otherwise —
> nothing crashes. Needs the EAS `projectId` in `app.json` (added by
> `eas init` / first `eas build`).
